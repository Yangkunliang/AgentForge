## 意图强制归类 bug 诊断（本日，待修复）
- 用户反馈：客户（用户）输入意图被"强制识别为全栈开发内容，即使不是开发内容"。
- 澄清语义：`SYSTEM_PROMPT`（engine.py:61）里的"面向全栈开发工程师"是**该 Agent 的能力训练倾向**（来自蒸馏进 AgentExpertise 的全栈经验），属 Agent 自身特质，**不是 bug**，不要去解耦它。
- 真正的致命 bug 在**用户意图被强制塞进开发流水线**（与 Agent 是否全栈倾向无关）：
  1. 前端 `web/src/stores/advancedSettings.ts:32` 默认 `?? 'iteration'`，聊天 payload 无条件带 `intent: iteration`。
  2. 后端 `catalog.py:374` `normalize_intent(None)` 兜底返回 `"iteration"`；`service.py:80` 空意图归一成它并钉死会话。
  3. `IntentType`（catalog.py:13 / types/index.ts:327）仅 4 种开发类目，无"通用对话"出口。
- 收窄修复方案（保留 Agent 全栈倾向，只修意图强制）：后端加 `general` 意图（单"对话"节点）+ `normalize_intent` 兜底改 `general`；前端 `?? null` 且 UI/类型补 `general`。用户尚未拍板是否动手。
- 教训：system prompt 的"全栈"= Agent 能力倾向（合法）；"用户意图被强制归类"= 真实 bug，二者不可混为一谈。
