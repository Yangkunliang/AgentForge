## 后端 .env 加载修复（TASK-055 · 配置优化）

用户指出后端(应在 src 里)有自己的 .env 且配了 LLM key，要求优化功能。核查发现真实问题：
- 项目存在 **三个 .env**：根 `.env`、`src/.env`（后端专属，237B）、`web/.env`。
- `src/agent_forge/config.py` 的 `_find_env()` 原本只加载**根 `.env`**，完全忽略了 `src/.env`。
- 两边 `LLM_API_KEY` 哈希一致(`3d6f388fa1ee`)，LLM key 值没问题；但 `src/.env` 多一个 **`MODEL_ROUTES`**(自定义模型路由) 而根 `.env` 没有 → 该路由此前被**静默丢弃**。
- `src/.env` 用 `API_KEY`/`DEFAULT_MODEL` 命名，`config.py` 只认 `LLM_API_KEY`/`LLM_MODEL`（虽同值但是隐患）。

修复（`src/agent_forge/config.py`）：
- `_find_env()` 改为返回列表 `[src/.env, 根 .env]`，`model_config["env_file"]` 直接用列表（pydantic-settings 第一个优先级最高）；`src/.env` 缺失自动回退根 `.env`。
- `api_key`/`default_model` 字段改用 `AliasChoices`，同时兼容 `LLM_API_KEY`/`API_KEY` 与 `LLM_MODEL`/`DEFAULT_MODEL`。
- 验证：改后 `model_routes_map` 正确载入 `src/.env` 的 vision/image_gen 路由；`api_key` 哈希不变；`database_url`(5433)/`redis_url`(6380) 仍取自根 `.env`，未破坏 Docker 连接。
- 已重启后端（新 pid 12314），`/api/v1/health` 直连与前端代理(3000→8000)均 HTTP 200，LLM `available=True`。
- 结论：后端现在真正以 `src/.env` 为权威后端配置，且兼容两套命名；之前的 `MODEL_ROUTES` 丢失 bug 已修复。

## src/.env 命名归一为标准键 + 修正 env_file 优先级方向 (TASK-055 续)
